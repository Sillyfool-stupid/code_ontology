# 使用指南：内网配置与逐步抽取

更新：2026-11-24。常用配置集中在 `.env`；新增阶段已实现，旧 CLI 和 YAML 保留兼容。默认中英文混合，源码标识符不强制翻译。无需为每个函数单独调用模型生成说明。


日常操作从本文开始。全部 Windows 命令使用 **CMD**，在项目根目录逐条执行；每一步成功后再继续。已有 `.env` 与模型配置无需重新填写。示例项目路径、输入仓库和输出目录都需要替换成内网实际位置。

## 先分清解析后端和图视图

| 后端 `CO_PARSER` | 视图 `CO_VIEW` | 提供的结构 |
|---|---|---|
| `joern` | `ast` | 抽象语法树：类、函数、语句、表达式等结构 |
| `joern` | `cfg` | 控制流图：分支、循环、语句执行路径 |
| `joern` | `cpg` | 综合代码图：当前实现支持的 AST、CFG、CALL、REF 等关系 |
| `tree-sitter` | `ast` | C/C++ 语法树，无需 Joern、Java 或编译器 |
| `tree-sitter` | `cfg` / `cpg` | 不支持，新版内网脚本会拒绝不兼容的视图 |

Joern 先生成基础 `cpg.bin`，导出原始节点边，再在 **normalize** 阶段按所选视图投影；AST 和 CFG 不是两个不同的 Joern 解析器。三种视图的输入包都保留源代码，区别是附加图上下文。CPG 不代表已完成全仓精确数据流分析。

Tree-sitter 的调用表达式只是语法节点，不代表已解析调用目标。它不执行宏求值或跨文件类型解析，预处理分支可能同时保留。`.c` 使用 C grammar，其余 C++ 扩展使用 C++；`.h` 如 C++ 解析有错误，会尝试 C 并选择错误较少的结果。检查 `raw/tree-sitter/parse_report.json`，错误节点保留，不将部分可用结构当成完整解析。

`auto` 在 Joern 工具缺失时选择 Tree-sitter，不在 Joern 执行失败后静默切换。做对比实验时明确指定后端；`CO_PROFILE` 是业务提示词方向（general / maintenance），与解析方式是不同维度。脚本每个会话只使用一个视图，不要写 `CO_VIEW=ast,cfg,cpg`。

## 1. 配置一次

首次部署先创建本机虚拟环境并安装依赖，不跨机器复制 `.venv`。在 Windows CMD 中：

```bat
cd /d "D:\code\code-ontology"
python -m venv .venv
call .venv\Scripts\activate.bat
python -m pip install -r requirements.lock.txt
python -m pip install -e .
```

已经完成环境准备则跳过以上安装。没有 `.env` 时才从 `.env.example` 复制；已有 `.env` 保留密钥和端点，参照模板补充 `CO_*` 配置。不要打印或提交真实环境文件。

首次部署如无环境文件，先执行 `if not exist .env copy .env.example .env`，再用 `notepad .env` 编辑。主要填写：

```dotenv
CO_REPO=D:/repos/my-project
CO_OUTPUT=D:/ontology-results/my-project
CO_EXPERIMENT=joern-ast-01
CO_PARSER=joern
CO_VIEW=ast
CO_PROFILE=general
CO_OUTPUT_LANGUAGE=mixed
CO_DISCOVERY_MODE=full
JOERN_HOME=D:/joern/joern-cli
OPENAI_BASE_URL=http://your-intranet-model/v1
OPENAI_API_KEY=unused
OPENAI_MODEL=your-intranet-model
```

`JOERN_HOME` 指向包含 `joern.bat` 和 `c2cpg.bat` 的目录。Tree-sitter 使用 `CO_PARSER=tree-sitter`、`CO_VIEW=ast`，不要求 Java 或 Joern。路径相对于所选 `.env` 目录解析；启动器从项目根执行。`CO_OUTPUT` 不能是输入仓库或其祖先，建议放在仓库外。

列表采用 JSON 数组，例如 `CO_INCLUDE_DIRS=["include"]`、`CO_SCAN_EXCLUDE=[".git","build","outputs"]`。`CO_SCAN_MAX_FILES=0` 为不限文件数；`CO_DISCOVERY_MODE=full` 为全部准备包参与发现；`sample` 使用 `CO_DISCOVERY_SAMPLE_LIMIT`。支持的源码/文本扩展名、扫描排除和文件大小上限仍生效，不等于扫描磁盘上任意文件。

配置优先级：显式 CLI 参数 > 系统环境变量 > `.env` > 显式 YAML > 内置默认。旧 CLI 的 `--exclude` 保留追加语义；环境列表整体替换。网页任务提交时冻结配置和提示词。脚本每次执行单步时解析一次配置、保存脱敏副本；下次命令可使用新预算，不影响已启动的当前阶段。

模型连接、密钥、模型名仅配置一次。`LLM_*` 为全局默认，下面四组允许分别覆盖 `CONTEXT_TOKENS`、`MAX_OUTPUT_TOKENS`、`TIMEOUT_SECONDS`、`MAX_RETRIES`、`CONCURRENCY`，留空继承：

```dotenv
LLM_DISCOVER_MAX_OUTPUT_TOKENS=4096
LLM_MERGE_CONTEXT_TOKENS=256000
LLM_MERGE_MAX_OUTPUT_TOKENS=65536
LLM_MERGE_SEND_MAX_TOKENS=true
LLM_MERGE_TIMEOUT_SECONDS=1200
LLM_MERGE_CONCURRENCY=1
LLM_EXTRACT_MAX_OUTPUT_TOKENS=4096
```

可在 `.env` 配置 `LLM_SEND_MAX_TOKENS=false`，不向服务端发送 `max_tokens`。也支持 `LLM_DISCOVER_SEND_MAX_TOKENS`、`LLM_MERGE_SEND_MAX_TOKENS`、`LLM_REVIEW_SEND_MAX_TOKENS`、`LLM_EXTRACT_SEND_MAX_TOKENS` 单独覆盖，留空继承全局。但省略参数不是取消服务上限：2026-11-25 本轮 DeepSeek 非思考模式实测多次在8192输出 token处返回 length。因此合并示例改为显式发送65536输出额度，超时1200秒。局部抽取与实例参数不联动修改。其他内网部署必须按其服务实际容量设置。

关闭发送后，`LLM_MAX_OUTPUT_TOKENS` 及阶段对应值仍是本地请求预算的输出空间预留，必须是正整数；它不再限制实际响应长度。实际生成长度由服务端默认输出上限与模型窗口决定，需要内网服务同步确认。程序继续检测 `finish_reason=length` 并保留原始响应、分批恢复，不将截断内容当作完整成功。多批多轮合并不等于跨请求无限上下文对话，最终全局 Schema 超过模型容量时仍可能无法收敛；此时保留候选和 partial 供继续处理，不能保证仅靠省略参数解决。所有变量逐项说明见项目根目录 `.env.example`。

以上输出值只是写法示例，必须满足内网服务容量和输入余量。提高合并输出不再影响局部提取或实例请求。`CO_MERGE_BATCH_ITEMS` 为合并批次条数上限，实际还受输入预算限制；合并当前逐批执行，`LLM_MERGE_CONCURRENCY` 是并发上限，设为大于 1 不会使当前顺序合并自动并行。`CO_DISCOVERY_BATCH_PACKS` 控制局部任务大小；实例默认每包一次，截断后再分片。未引入不生效的实例批量开关。


## 2. 四种解析方式的完整命令（Windows CMD）

### 2.1 共同设置

保留 `.env` 中已跑通的模型连接。下面的配置写入 `.env`，不要在终端设置变量：

```dotenv
CO_REPO=D:/repos/your-cpp-project
CO_PROFILE=general
CO_OUTPUT_LANGUAGE=mixed
CO_DISCOVERY_MODE=full
CO_SCAN_MAX_FILES=0
```

保存 `.env` 后逐条执行：

```bat
cd /d "D:\code\code-ontology"
```

`.env` 中的 include/exclude、单文件大小上限仍生效，先检查扫描清单。全量发现表示遍历全部纳入的准备包，不保证语义零遗漏。若未配置 Joern 路径，在 `.env` 中补充：

```dotenv
JOERN_HOME=D:/joern/joern-cli
```

下面 `.bat` 自动使用项目 `.venv`。命令可用 Python 等价替换，例如：

```bat
.venv\Scripts\python.exe scripts\intranet.py scan
.venv\Scripts\python.exe scripts\intranet.py merge-schema
```

如需新写一个批处理文件串联这些命令，每次调用 `intranet.bat` 前加 `call`，并检查 `errorlevel`；下面示例供 CMD 逐行执行。

### 2.2 Joern AST：推荐先跑的基线

在 `.env` 中修改本组的后端、视图、实验名称和独立输出根目录：

```dotenv
CO_PARSER=joern
CO_VIEW=ast
CO_EXPERIMENT=baseline-joern-ast
CO_OUTPUT=D:/ontology-results/joern-ast
```

逐步执行；其中 discover-local、merge-schema、review-schema、extract 会请求真实模型：

**`init`：初始化实验会话，保存仓库、视图和输出身份。**

```bat
scripts\intranet.bat init
```

**`config`：查看脱敏后的生效配置，确认后端、视图与文件范围。**

```bat
scripts\intranet.bat config
```

**`check`：检查配置与本地依赖，不请求真实模型。**

```bat
scripts\intranet.bat check
```

**`doctor`：诊断解析器环境，不请求真实模型。**

```bat
scripts\intranet.bat doctor
```

**`scan`：扫描文件、保存 manifest 与不可变源码快照。**

```bat
scripts\intranet.bat scan
```

**`parse`：运行解析器，生成原始节点边；Joern 还生成 cpg.bin。**

```bat
scripts\intranet.bat parse
```

**`normalize`：将原始图转换成所选视图，建立图索引。**

```bat
scripts\intranet.bat normalize
```

**`prepare`：按函数、类型和文件片段生成带源码证据的输入包。**

```bat
scripts\intranet.bat prepare
```

**`discover-local`：调用大模型，分批生成局部 Schema 并保存检查点。**

```bat
scripts\intranet.bat discover-local
```

**`merge-schema`：调用大模型，独立合并局部 Schema 并保存轮次和检查点。**

```bat
scripts\intranet.bat merge-schema
```

**`review-schema`：独立 AI 对照来源和源码审查、修正 Schema，保留原始草稿。**

```bat
scripts\intranet.bat review-schema
```

**`extract`：调用大模型，按固定 Schema 分批抽取实体、关系、属性和规则。**

```bat
scripts\intranet.bat extract
```

**`finalize`：本地汇总批次、校验去重，生成 final；不调用模型。**

```bat
scripts\intranet.bat finalize
```

**`validate`：检查最终结构、引用与源码定位；不等于语义正确率。**

```bat
scripts\intranet.bat validate
```

**`report`：生成结果报告，不调用模型。**

```bat
scripts\intranet.bat report
```

**`status`：显示会话、实际快照、阶段状态与日志位置。**

```bat
scripts\intranet.bat status
```


需要额外测试模型连接时执行下面一条；模型已经跑通可跳过：

```bat
scripts\intranet.bat doctor --with-llm
```

也可以只测试模型，不依赖 Joern、不初始化实验。在工具项目根目录的 Windows CMD 中执行：

```bat
call .venv\Scripts\activate.bat
python scripts\check_model.py
```

脚本读取项目 `.env` 与系统环境中的共享模型连接，每次发起新的真实模型探测；不读取业务源码、不启动抽取流程。默认使用全局 LLM 参数，关闭网络错误自动重试；JSON 协议自动降级或一次响应修复仍沿用现有客户端规则。需要测试合并阶段参数或指定环境文件时：

```bat
python scripts\check_model.py --stage merge --timeout 1200
python scripts\check_model.py --env-file D:/configs/intranet.env
```

`--stage` 支持 global、discover、merge、review、extract；`--timeout` 仅覆盖本次探测。诊断保存在 `outputs/model-check/<本次标识>/result.json` 和同目录的 `llm_requests/`，可用 `--out` 更换诊断输出根目录，不修改实验配置和缓存。退出码 0 为探测通过，1 为请求或响应检查失败，2 为配置无效。超时显示 unknown，服务端可能仍在执行，确认服务状态后再显式重试。模型连通不代表抽取质量或大输入任务已验证。

### 2.6 续跑、自动串联与其他终端

**`.env` 配置在新终端仍然有效。** 激活环境后先运行 `status`，再运行失败或尚未执行的那一步。同一实验保持仓库、后端、视图、profile、输出根和实验 ID 一致。更换视图或输入仓库时新建实验。

普通单步不补跑上游。明确要串联时可以使用下面命令，失败即停止：

```bat
scripts\intranet.bat init
scripts\intranet.bat run --to discover-local
scripts\intranet.bat merge-schema
scripts\intranet.bat run --to report
```

可选本地自检：

```bat
scripts\intranet.bat smoke
```

smoke 使用真实 Tree-sitter + 内置本地模拟模型，不读取用户模型参数，不评估语义质量；默认报告为项目 `outputs/intranet-smoke/verification.json`，可用 `--out PATH` 指定另一输出根。

自定义环境文件统一加 `--env-file D:/configs/project.env`；可选 `--config PATH` 兼容 YAML。不要在 init 时临时指定一个仓库、后续又由 `.env` 读到另一个仓库。

PowerShell、CMD、Linux/Git Bash 都先编辑同一份 `.env`，无需设置终端环境变量。PowerShell 激活 `. .\.venv\Scripts\Activate.ps1` 后运行 `python scripts\intranet.py scan`；Linux/Git Bash 激活 `.venv/bin/activate`，通过 `sh scripts/intranet.sh scan` 调用相同入口。CMD 不直接运行 `.sh`。

会话保存实际快照，不猜“最新目录”。scan 后源文件变化，应重新 scan；不要手改 source 快照。脚本与工作台共享输出写锁，历史 CLI 未纳入启动器父锁，不要并发写同一输出。

## 3. 阶段边界和产物

设 S 为 status 显示的快照，R 为 `S/runs/实验ID/视图/profile`：

| 阶段 | 输入 | 主要输出 | 模型 |
|---|---|---|---|
| scan | 输入仓库、扫描/解析配置 | S/manifest.json、source、policy.json | 否 |
| parse | 已扫描快照，核对当前仓库未变 | raw/cpg.bin 与 raw/cpg；或 raw/tree-sitter | 否 |
| normalize | 完整原始图 | normalized/视图、graph.sqlite、symbols.jsonl | 否 |
| prepare | 规范图、源码、预算 | prepared/视图/packs.jsonl、index.json | 否 |
| discover-local | 当前证据包、发现参数/提示词 | R/schema/local/、local-manifest.json、selection.json | 是 |
| merge-schema | 当前且完整的局部发现清单 | R/schema/merge/、rounds/、draft-schema.json、schema.json、unresolved.jsonl | 是 |
| review-schema | 合并草稿、来源映射、相关源码证据 | R/schema/review/、review-report.json、review-status.json、schema.json | 是 |
| extract | 固定 Schema、准备包 | R/extraction/manifest.json、selection.json、每批 JSON | 是 |
| finalize | 成功且指纹匹配的实例批次 | R/final/各类 JSONL、metrics.json、report.md | 否 |
| validate | final、源码证据 | R/validation.json | 否 |
| report | 最终指标和产物 | R/report.md | 否 |

Joern parse 仍包含从 cpg.bin 导出原始节点边，这是一项解析器适配操作；不再隐式规范化。旧 `python -m code_ontology parse` 默认保留“扫描+解析+规范化”兼容行为，用 `--raw-only` 可跳过规范化。旧 discover 为发现+合并，AI 审查独立可选；新增 `discover-local` 与 `merge-schema` 独立入口。旧 extract 默认归并，`--defer-finalize` 可仅生成批次。新内网脚本默认按表格边界执行。

final 包含 schema.json、entities.jsonl、relations.jsonl、attributes.jsonl、rules.jsonl、candidates.jsonl、conflicts.jsonl。它们不是每个函数的功能文档。业务知识保留 evidence_ids；不强制把所有工具类变成业务概念。

会话及逐阶段日志：`CO_OUTPUT/sessions/实验ID.json`、`sessions/实验ID/阶段-时间戳.log` 和 `.config.json`。模型原始回答、finish_reason、参数在 R/llm_requests。日志记录北京时间并带 +08:00；历史 UTC 记录保持原值，网页任务展示时转换为北京时间。

Schema 阶段的范围与成本摘要保存在 `R/schema/cost-coverage.json`，按 discover、merge、review、extract 追加记录任务数、完成范围、耗时及服务返回的 usage。usage 缺失保持未知；该文件是运行审计，不是语义质量评分。输出根的 `experiments/实验ID/视图-profile/index.json` 提供实验优先入口，列出状态、审查来源、主要产物路径及是否存在，底层快照和 run 目录不迁移。


### 3.1 输出目录怎么找、先看什么

运行 `scripts\intranet.bat status` 查看真实快照和实验路径。以 Joern AST 为例，`<snapshot_id>` 是实际标识，不要照抄别的机器的哈希：

```text
D:/ontology-results/joern-ast/
├── sessions/
│   ├── baseline-joern-ast.json
│   └── baseline-joern-ast/              各阶段日志与脱敏配置
└── <snapshot_id>/                      快照 S，直接位于输出根下
    ├── manifest.json
    ├── source/
    ├── raw/
    ├── normalized/ast/
```

## 4. 合并耗时长时单独恢复

局部发现结束后可以退出，再单独执行 merge-schema。合并检查局部清单、全部包、采样范围、提示词及发现参数指纹；不匹配或部分完成时要求重跑 discover-local，不混用目录里残留的旧 JSON。

合并首先按源码目录分组处理，再多轮归并。每批检查点按输入、实际提示词、该阶段生效参数和契约计算键。调用开始、轮次/批次和日志路径均输出；模型等待每 15 秒报告已等待时长。这里目录分组不是编译器确认的业务模块，也不代表已解析跨文件调用。

```bat
scripts\intranet.bat status
scripts\intranet.bat merge-schema
```

原命令重跑复用已成功批次，局部发现请求新增为零。修改 LLM_MERGE_* 只影响合并检查点，不使局部模型缓存失效。仅修改超时或重试值也属于该阶段参数变化，会重新计算该阶段键；原始旧结果仍保留。

截断与超时处理：

- finish_reason=length 仍被检测并保留原始回答。局部发现/实例任务自动拆分，成功子任务可复用；不会接受可解析但已截断的 JSON。
- 合并批次截断时拆成更小批次；若无法继续缩减，保存部分状态，保留完整候选，停止宣称全局成功。单个 Schema 本身太大时不保证可以自动拆成满足所有引用的更小 Schema。
- 预算/恢复次数有界。不能简单拼接续写 JSON，也不能靠无限 timeout/max_tokens 保证完整。
- 客户端超时、HTTP 408/504 标为 unknown，不立即重发。先检查服务端是否仍计算，再显式运行原命令。普通 chat completions 无任务查询能力时，无法保证取回已断开的回答，也无法保证显式重试不会产生重复服务端计算。
- 其他连接错误仍使用有限重试；鉴权/配置错误快速失败。进度只反映已知任务和已等待时间，不伪造模型内部百分比。

合并产物：

```text
schema/local-manifest.json   局部成功范围、参数与候选
schema/merge/*.json          按内容寻址的成功批次
schema/merge/*.task.json     每批任务状态、失败或 unknown
schema/rounds/*.json         各轮中间结果
schema/merge-status.json     当前合并状态
schema/source-mapping.json   每个局部源项到最终 ID 的映射及批次审计路径
schema/draft-schema.json     合并原始草稿，后续审查不覆盖此文件
schema/draft-source-mapping.json  合并时原始来源映射
schema/unresolved.jsonl      未对齐、端点变化、类型或单位冲突等程序问题
schema/review/*.json         AI 审查修正批次与检查点
schema/review-report.json    审查发现、修正记录与剩余问题
schema/review-status.json    审查状态与输入、参数及结果指纹
schema/review-candidate.json 最近审查批次结果；审查失败时仍可回查
schema/history/             每次执行、每轮、每批的独立 Schema 和映射，旧版不覆盖
schema/module-schemas.json   合并失败时保留的候选集合
schema/schema.json          最近成功合并的全局 Schema
```

合并请求为每个输入类、关系和属性分配唯一来源 ID。模型返回 `ontology` 与 `source_mapping`；允许改名和真正同义项归并，不靠名称相等判定覆盖。程序检查目标类别、引用并记录关系方向、属性类型与单位等差异，自动保留来源名称为 aliases、合并证据，并跨轮组合到最终 ID。完整审计单独写在 source-mapping.json，不混入业务 Schema。该映射证明条目去向可追溯，不能证明模型的语义等价判断正确。

`module-schemas.json` 是候选集合，不等于已对齐的全局本体；旧 schema.json 可能仍在磁盘，必须结合 merge-status 和指纹检查。合并首先输出合法 JSON/ID 引用的 schema.json 与原始草稿，质量状态为 pending_ai_review；未对齐、方向或类型差异写入问题清单，不再因旧版名称覆盖检查而停止输出。JSON 结构、引用、证据或映射格式仍有问题时触发一次修复，失败批次保留原始回答和候选。改名本身不触发遗漏失败。本次升级不改变局部提示词；已有匹配的 local-manifest 可直接运行 merge-schema，新合并契约会使旧合并检查点失效，无需删除结果。

### 每轮、每批 Schema 历史在哪里

`R/schema/history/` 下，每次执行单独生成 `merge-时间-唯一编号/` 或 `review-时间-唯一编号/`。续跑可复用模型检查点，但仍新建一次历史，不覆盖上次记录。`manifest.json` 索引各版本及状态。

```text
schema/history/merge-时间-唯一编号/
  input/schema-001.json                       本轮合并的局部输入候选
  round-001/batch-001/candidate-001/schema.json 模型返回的未校验候选
  round-001/batch-001/result/schema.json        此批通过结构校验的结果
  round-001/result/schema-001.json             第一轮输出候选之一
  round-001/result/schema-002.json             第一轮尚有多个候选时全部保存
  round-002/result/schema.json                 第二轮收敛结果
  final/schema.json                           本次合并输出
  manifest.json
```

每个版本旁有 `mapping.json`（来源映射/多轮追溯）和 `metadata.json`（状态、问题、检查点）。`candidate_not_validated` 不能解释为通过；审查历史使用相同目录结构。预算拆分产生 `part-1/part-2/`，成功子批次立即保存，不等整轮结束。中断时已完成批次仍在；未完成整轮不会伪造整轮结果。合并草稿仍为 `draft-schema.json`，AI 审查只发布新的 `schema.json`。

只读浏览器的「本体图谱 → 本体结构 → Schema 版本」可以选择这些历史，查看合并或审查每轮、每批的图。切到「抽取实例」始终使用与最终实例配套的 Schema，历史选择不会改写结果或调用模型。

### 4.1 合并后可选 AI 审查与修正

推荐顺序：

```bat
python scripts\intranet.py merge-schema
rem 可选：python scripts\intranet.py review-schema
python scripts\intranet.py extract
python scripts\intranet.py finalize
python scripts\intranet.py validate
python scripts\intranet.py report
```

review-schema 对照局部原始来源项、当前映射、程序问题和相关源码证据审查，并输出修正后的完整 Schema。按 CO_REVIEW_BATCH_ITEMS 分批来源，每批保留完整当前 Schema，避免暗中丢弃全局关系；输入/输出截断时拆分来源批次，成功子批次续跑复用。当前 Schema 本身超出服务窗口或输出容量时仍可能无法完成；此时保留草稿、最近候选、报告及 partial，不裁切文件来假装成功。CO_REVIEW_MAX_ROUNDS 限制最多修正轮数；每轮结束仍有未解决错误时，只对剩余来源项再审，耗尽后标记 partial，警告保留在报告中。局部 Schema 也是模型假设：AI 可根据源码修正原来的类、关系端点或属性类型，但必须在 fixed 问题中列明来源 ID、目标 ID、具体源码理由并保留证据。程序记录这类 AI 修正，与真正尚未解决的结构差异分开；目标后续改变时旧修正决定失效。AI 审查不是人工验收。

LLM_REVIEW_* 与合并、抽取参数隔离；连接和模型共用 OPENAI_*。只重跑审查不会重新局部抽取或合并。修改审查参数/提示词会改变审查指纹，已完成的同输入批次才可复用。

### 4.2 合并后直接抽取实例

merge-schema 成功保存合法 Schema 后，直接执行 `python scripts\intranet.py extract`，接着 finalize、validate、report。网页也可直接点击“抽取实例”。AI 审查是可选步骤，内网 `run` 默认跳过；显式运行 review-schema 或 `run --to review-schema` 才执行审查。

schema-scope.json 与报告如实记录 merged_unreviewed 或 ai_reviewed_not_human_verified。未审查不代表审查通过；合并指纹、JSON/ID 引用、源码证据和实例类型校验仍生效。旧 CO_ALLOW_UNREVIEWED_SCHEMA 配置保留兼容，false 也不再强制审查。普通 CLI 如需明确要求审查，可给 extract 添加 `--require-schema-review`。工作台冻结 Schema 仍检查与当前实验一致。

如果模型无法容纳全局 Schema，可由人工选择某个已保存候选中的 `schema` 对象，另存为合法 Ontology JSON，并在独立实验中显式指定：

```bat
scripts\intranet.bat extract --schema D:/ontology-results/reviewed-module-schema.json
```

显式选用的 Schema 必须引用当前快照有效证据；schema-scope.json 标明人为选定范围，不能当作全局合并完成。不要手改原检查点或原始回答。新实验需先 init、scan、parse、normalize、prepare，原始解析缓存可在相同输出根复用。
