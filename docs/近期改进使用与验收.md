## 网页执行输出

“任务日志与历史”的执行过程面板可选择网页任务或同一输出根的 CLI 执行。显示真实初始批次的已结束、成功、失败、unknown 和剩余计数，附请求耗时、服务返回的 token 用量、缓存和拆分事件。支持级别/关键词筛选、跟随输出、重新读取和完整文本日志。事件按字节游标增量读取；界面最多保留最近 500 条，磁盘历史不删除。

模型请求结束后，点击“查看本次输出”优先展示模型回答，可展开完整请求。大文件保留分段查看。非流式接口在响应结束前只显示等待和阶段事件，不能显示模型内部推理、真实完成百分比或逐 token 回答。usage 缺失不会按零计费或推断精确 token。

顶栏支持返回页面、阶段和产物路径；路径选择、执行计划、任务副本、详情和证据也有返回入口。本体嵌入页隐藏重复侧栏，并支持返回工作台；尚未移除 iframe。

可以在抽取期间打开网页、查看日志和产物，这些动作不调用模型。启动器与网页共享输出根写锁，因此同一输出根即使使用不同实验名，也会阻止同时写入。旧普通 CLI 不持启动器父锁，禁止与网页并发写同一快照或实验。独立输出根可隔离磁盘写入，但仍共享模型服务容量。

当前任务结束后，再重启工作台加载服务端改动：

```powershell
. .\.venv\Scripts\Activate.ps1
python -m code_ontology.workbench --port 8766
```

运行中的进程保留已冻结参数。新代码不会追补旧任务的结构化事件；旧 intranet 会话仍可读取已有文本日志。

## 分步骤配置和局部发现性能

可选示例在 `configs/intranet/run.yaml`。它引用 steps 下的明确文件，路径相对于声明文件解析；旧平铺 YAML 仍可用。`--config` 支持 YAML 文件或包含 run.yaml 的目录。

```powershell
. .\.venv\Scripts\Activate.ps1
python -m code_ontology.intranet config --env-file .env --config configs/intranet
```

先检查最终参数与来源。环境中的相同字段优先于 YAML；阶段显式值优先于全局默认。模型、连接、密钥仍统一在 `.env`，不能写入 YAML。现有 `.env` 的仓库、输出根、实验名和提示词路径也可能覆盖示例，不能直接假定会创建 optimized-01。确认独立实验身份及输出根后，再按 init、scan、parse、normalize、prepare、discover-local 等正常步骤执行。

`CO_DISCOVERY_STRATEGY` 支持：

新增可选 `ast-01`：保留原 AST 方案，按源码范围组批并共享重叠证据。仅用于 `ast`，默认不启用；独立实验的配置和验证见 [AST-01使用与验证](AST-01使用与验证.md)。

- `auto`：已有局部清单沿用保存策略，旧清单没有策略时使用 legacy；新实验使用 budget。
- `legacy`：保留固定包数组批，适合旧实验恢复。
- `budget`：同模块确定性排序，按完整请求预算及包数上限组批；批内完全相同的源码/图节点使用共享引用，仅在确实减少序列化体积时启用。

`CO_DISCOVERY_BATCH_PACKS` 是上限，不保证每批填满。单包超限或输出截断仍进入有界拆分。保留完整 prepared 包、源码范围、证据 ID 和图边，不通过抽样或删除 FILE 包宣称全量加速。新示例使用上限 8、并发 2；实际仍以生效配置为准。

并发、超时和重试从响应缓存身份分离，实际输入、提示词、契约、模型、端点和响应参数仍参与身份。旧局部检查点按保存的原始指纹及证据重新验证后迁移；普通旧 LLM 响应缓存只做精确旧键兼容。不要承诺所有旧缓存在任意参数变更后都能复用。更换端点、模型或提示词后，应使用独立实验；原成功产物不会自动重新生成。

`schema/local-tasks.json` 冻结本次批次清单，`local-manifest.json` 记录阶段耗时及请求统计。`executions/<execution_id>/events.jsonl` 保存 CLI 事件；网页任务事件保存在工作台 jobs 下。实验入口为 `experiments/<experiment>/<view>-<profile>/index.json`，引用原来的快照/run 路径，不搬迁旧结果。

## 审查、提示词与额度诊断

`schema/review-issues.json` 保留 AI 问题生命周期。上一轮未解决的问题不会因下一轮未提及而自动关闭。关闭需要显式 fixed；所有记录均标记尚未人工确认。

`CO_REVIEW_MAX_REQUESTS`、`CO_REVIEW_MAX_SECONDS`、`CO_REVIEW_MAX_TOKENS` 默认为 0，即不增加预算限制。每次请求前检查，含修复/重试；时间预算不能中断已提交请求。启用 token 预算时，以已知用量加下次请求保守预留判断，usage 缺失则停止追加请求。预算耗尽保留 partial 和检查点；这些预算按一次阶段执行计，续跑会建立新的执行预算。

新原则和属性类型/单位提示位于 `code_ontology/resources/prompts-v2`，旧 prompts 不变。通过独立实验的 prompt_dir 或 CO_PROMPT_DIR 显式选择 v2；程序类型检查、候选和冲突保留，不能把提示词改进视为抽取质量已提高。

有限额度诊断先运行无请求预览：

```powershell
python scripts/check_model_limits.py --env-file .env --limits 1024,2048,4096 --dry-run
```

去掉 `--dry-run` 才会提交真实模型请求；`--without-cap` 是额外一次显式省略 max_tokens 的对照。工具不扫描源码、不写正式实验；超时 unknown 后停止后续档位。额度被接受、length、提前停止和服务理论上限是不同结论。
