## 当前流程与恢复入口

推荐独立阶段顺序：`init → scan → parse → normalize → prepare → discover-local → merge-schema → extract → finalize → export-rdf → validate → report`。`review-schema` 是合并后的可选 AI 审查，未审查时记录真实来源状态；人工语义审核另行执行。`export-rdf` 不调用模型，可对已有归并结果单独导出；内网 `run` 包含它，旧普通 CLI `run/experiment` 不自动导出。

| 任务 | 入口与边界 |
|---|---|
| 确认实际快照和当前阶段 | `scripts\intranet.bat status`，不猜最新目录 |
| 局部发现或合并失败 | 同配置执行原步骤，成功检查点可复用；超时 `unknown` 先核查服务状态再显式续跑 |
| 设置阶段失败补跑 | `CO_DISCOVERY_PASS_COUNT`、`CO_MERGE_PASS_COUNT` 含首次执行，默认 1；与单请求重试和合并层数不同 |
| 调整实例批量 | `CO_EXTRACT_BATCH_PACKS` 默认 1，与 `LLM_EXTRACT_CONCURRENCY` 独立；修改后先 extract 再 finalize |
| 比较 AST-01 | `CO_VIEW=ast`、`CO_DISCOVERY_STRATEGY=ast-01`，使用独立实验；AST-01 不是解析后端或新视图 |
| 确认结果可用范围 | 分别检查阶段状态、validate、RDF/SHACL 和人工标签；结构通过不等于业务语义正确 |

以上为项目根目录下的 Windows CMD 命令。PowerShell、Linux 与 Git Bash 的激活方式见使用指南；配置变量逐项说明见项目根目录的 [`.env.example`](../.env.example)。
