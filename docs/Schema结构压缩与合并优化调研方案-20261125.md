# Schema 结构压缩与合并优化调研方案

> 历史记录：下文的“当前”、配置、测试与待实现项均针对文中日期和被测版本。后续实现状态见 [改进想法](改进想法.md) 与 [近期改进使用与验收](近期改进使用与验收.md)，当前命令见 [使用指南](使用指南.md)，全部文档见 [文档导航](README.md)。本次整理保留原始数据，未重跑模型或规模实验。

日期：2026-11-25，北京时间。范围：mini-plant 的局部 Schema 发现与全局合并，以及后续整仓扩展。本文是调研与设计，没有修改抽取逻辑，也没有发起新的真实模型请求。

## 1. 建议结论

应当让 AST/CPG 承担本地结构索引、证据组织和依赖筛选，而不是把更多图数据直接交给 LLM。同时需要改变合并协议：让模型判断有歧义的概念匹配，由程序维护完整 Schema、来源映射和版本。仅缩短输入，无法解决当前合并中的推理与重复输出成本。

实施顺序建议为：先做可逆去重、单候选透传和输出预算控制；再做 AST 证据骨架与候选匹配；最后补充真实依赖切片及跨快照增量更新。第一轮不增加逐函数 LLM 摘要、不引入新的外部模型服务。

代码定位与问题：

| 模块 | 当前行为 | 优化含义 |
|---|---|---|
| `prepare.py` | 按符号生成源码与 AST 上下文；节点数量截取，超预算从尾部删节点 | 改成按证据作用组织，避免关键条件恰好被截掉 |
| `discovery.py` | 同一批次共享完全相同的代码/节点；主要按目录与包 ID 排序 | 按所属类型、源码范围组织批次，扩大可复用范围 |
| `stages.py` | 每批调用合并，包括单候选；以候选份数和输入预算分批 | 增加概念项数、预期映射输出预算；单候选直接保留 |
| `schema_merge.py` | 返回完整本体及逐项 `source_mapping` | 多轮重复输出成本高，适合改为局部决策协议 |
| `joern.py` | 当前 cpg 边集合包含 AST、CFG、CALL、REF、类型等 | 尚无 CDG/REACHING_DEF，不能直接宣称支持完整控制/数据依赖切片 |

最值得借鉴的是“结构组织、依赖保留、候选筛选”，不是直接照搬论文中的压缩率。代码补全已有明确查询目标；全量 Schema 发现需要先遍历全部纳入范围的结构单元，再为每个单元建立发现任务或明确的复用记录。

## 4. 分阶段实施设计

### P0：冻结基线，形成离线成本报告

保留当前快照和实验，分析已有请求，不重新调用真实模型。报告按阶段列出实际 usage、reasoning、请求耗时、截断、unknown、修复次数、缓存命中和覆盖范围。将源码字节、序列化字节、估计 token 与服务端实际 usage 分列。

建立每个符号及源码范围的清单，区分已提交、复用、未处理、解析异常、等待恢复。所有阶段都能定位首次遗漏的位置。新策略使用独立实验 ID，不覆盖 workbench-03。

### P1：可逆去重与合并成本控制

1. **共享证据内容。** 使用源码内容哈希与定位建立本地证据表，保留包角色、所属作用域和上下文差异。重复正文只在同一请求中发送一次，其他包通过请求内短 ID 引用；不同请求不能引用模型尚未收到的字典。相同源码但不同上下文必须合并上下文或保留独立任务，不能只按文本删除。
2. **缩短模型侧元数据。** 请求内使用 E1、N1 等短 ID，路径、文件 SHA、重复警告及完整审计信息保存在本地可逆映射中。语义相关警告仍需发送。模型返回后严格验证 ID，恢复正式来源标识。
3. **单候选合并透传。** 不调用 LLM，执行确定性的合法性校验、规范化与 lineage 组合，保存与普通批次一致的检查点和历史。若需改写定义，应由显式修订任务承担。
4. **同时控制输入与输出。** 分批同时考虑候选项数、定义长度、映射条数及输入 token，而不是只限制 Schema 份数。根据已有请求校准保守输出预算；单个大 Schema 可按概念及依赖拆分，跨块引用保留为明确的外部引用。

验收重点：全部证据可逆回查，重复包仍有覆盖记录，单候选新增模型请求为零；大候选拆分后引用合法，失败子任务可续跑。新策略需要独立指纹，不能误用旧请求结果。

### P2-A：AST 骨架与行为证据分层

将模型输入组织为两部分：

- **结构骨架**：命名空间、类型与继承声明、字段及类型、枚举、常量、函数签名、必要注释及源码引用。
- **行为证据**：构造与赋值、条件判断、状态变更、校验、调用及副作用等语法块；保留操作对象、条件、阈值、单位、异常分支和定位。

TYPE_DECL 不再重复携带全部方法正文，方法证据引用所属类型骨架。文件级包处理未归属代码，避免再次携带已覆盖正文。声明与定义对应关系通过解析器信息和作用域核查，不能仅用同名关联。

所有纳入范围的函数仍经过结构分析。不确定、宏展开缺失、解析错误、复杂指针、间接调用或跨函数条件无法确认时，扩大上下文或回退完整片段，并记录原因。骨架不足时补充原始源码，不增加“先由 LLM 摘要全部函数”的固定阶段。

这一步先用现有 AST 实现。AST 可以识别语法结构及条件祖先，不能证明调用目标、数据来源或路径可达性。

### P2-B：将全量重写改为候选匹配与增量决策

建立本地概念注册表，保存概念、来源证据、别名、关系、版本及待确认项。具体流程：

1. 对可证明同源同义的完全相同项进行确定性复用；同名异义不能直接合并。
2. 使用类别、命名空间、结构签名、已有别名和词汇检索生成匹配候选。先采用本地检索；若以后需要向量模型，应单独评估资源和端点。
3. 模型只判断候选组中的 equivalent、distinct、unresolved，并在必要时返回名称或定义修订，不重复输出整个全局本体和全部来源映射。
4. 程序应用决策，维护来源映射、合并别名和证据，检查关系端点、属性所属、类别兼容及决策冲突。语义等价存在冲突时不能盲目做传递合并。
5. 模块内处理后执行跨模块候选检索。检索失败或候选预算不足的项保留为独立候选/待确认，不把“没有召回匹配”当成已证明不同。
6. 由程序物化最终 Schema；全局 Schema 不再必须装入一次模型响应。后续实例抽取也可按代码单元选取相关 Schema 子集，但需独立评估覆盖与跨模块关系。

这一阶段改变输出契约，必须升级 merge format、检查点与缓存版本。现有规范 ID 依赖名称和定义，注册表的稳定内部 ID 应另行设计；通过版本映射兼容外部 ID，不直接修改旧历史。

候选筛选可能漏掉异名同义概念，因此需要跨模块复核、召回抽样和人工审查。不能为减少请求强制合并，也不能把保留重复候选误报为完成语义对齐。

### P3：补充真实 CPG 依赖切片和跨快照增量

需要语义依赖时，先补齐 Joern overlay、导出与边能力元数据，验证数据依赖及控制依赖确实存在。以字段写入、状态迁移、业务分支等为种子，保留有界依赖闭包、语法祖先与必要调用边界。预算不足时报告缺失依赖并回退扩大输入，不能静默裁掉条件。

不是对整张 CPG 做固定 h-hop 后全部发送。图规模越大，任意扩邻居越可能增加成本。切片应明确目标、边类型、边界和未解析关系；Tree-sitter 路径继续明确标为 AST。

跨快照复用使用源码内容、所属作用域、依赖、解析配置、视图、提示词、模型和阶段参数等指纹。文件变化后重新定位行号并核验源码，不能复用旧文件 SHA/位置来冒充当前证据。头文件、宏、类型与被调函数变化需要失效传播；删除源码时撤销其支持，仍有其他证据的概念继续保留。

## 5. 验证与决策标准

采用固定 mini-plant 快照做基线，并准备包含跨模块同名异义、异名同义、条件阈值、宏、删除与依赖变化的结构回归样例。自动化测试使用本地模拟模型，覆盖短 ID 恢复、单候选透传、候选漏召回状态、决策冲突、截断拆分、续跑和缓存失效。

| 维度 | 比较内容 | 通过要求 |
|---|---|---|
| 范围 | 文件、符号、片段、复用及未完成清单 | 每个纳入单元有明确去向；覆盖率不冒充语义召回率 |
| 来源 | 引用、内容哈希、源码位置及映射 | 无悬空、伪造或静默丢失 |
| 成本 | 输入/输出/reasoning、失败消耗、缓存首次与续跑 | 使用实际 usage，未知消耗单列 |
| 时间 | 准备、检索/压缩、模型等待、重试及总墙钟 | 核算新增本地计算，不能只比较 prompt 长度 |
| 结构 | ID、属性所属、关系端点与跨块引用 | 自动校验通过且历史可恢复 |
| 语义 | 概念、关系、规则、条件及同义合并错误 | 按固定规程由人工评审，Agent 不代填标签 |

建议先分别做 P1 各项消融，再比较 AST 骨架与候选合并。真实模型 A/B 使用相同模型、提示词版本及阶段参数记录，独立实验 ID；这是后续实施验收工作，本次没有执行。压缩率或速度目标应在基线固定后设定，不能从论文比例推算项目收益。

实现后的相关检查包括局部单元测试及 `python -m unittest discover -s tests -v`。涉及 Joern 导出时增加 `python scripts/check_demo.py --real-joern`；涉及工作台编排时按项目规程执行对应检查。这些检查使用模拟模型的部分不能证明真实业务语义质量。

## 6. 推荐第一批交付范围

第一批实现 P0、P1 和 AST 骨架原型：成本报告、证据共享与可逆短 ID、单候选透传、概念数量/输出预算分批、覆盖清单。用独立实验比较后，再替换合并协议。这样能先获得可测的改进，也避免一次同时修改解析图、证据契约和合并语义，难以定位质量变化。

本次只增加本方案文档。既有快照、workbench-03 正式产物和正在运行的任务保持原样。语义损失、候选召回率以及内网网关推理参数的实际行为，仍需后续验证。
