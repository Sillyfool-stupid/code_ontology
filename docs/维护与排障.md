# 维护与排障

日常配置与逐步命令统一见 [使用指南](使用指南.md)，全部文档见 [文档导航](README.md)。本文面向内网迁移、故障定位与 Agent 接手，维护日期：2026-11-26（北京时间）。

## 1. 接手原则

- 先读项目根目录 AGENTS.md，确认实际项目目录、shell、输入仓库、输出根、实验 ID、后端、视图及当前阶段。不照抄外网路径或快照哈希。
- 常用配置集中在 `.env`，YAML 可选兼容；优先级为 CLI > 系统环境 > `.env` > YAML > 默认。提示词单独保留在 resources/prompts。不要打印完整 `.env` 或密钥。
- 常用配置写入 `.env`，无需在 CMD/PowerShell 中 set 实验变量；直接调用 Python 时先激活本项目 `.venv`，或使用其解释器绝对路径。Agent 的不同 shell 调用可能不共享环境。
- 输入仓库与 `source/` 不可手改。先检查纳入范围、解析图和证据包，再判断模型问题。
- 同实验原命令用于恢复，新实验 ID 用于独立对比。不先删缓存，不并发写同一输出。
- 不自动切换公网模型、不自动执行输入仓库的构建脚本。普通步骤不得隐式执行上游模型任务。
- 流程完成、结构合法、源码语义支持和业务有用分层判断。人工标签由人填写，不冒充人工确认。

## 2. 优先排查顺序

1. 用 `scripts\intranet.bat config`、`check`、`status` 检查生效配置、阶段、实际快照和日志。
2. 确认 `.venv` 解释器、Java 与 Joern 路径。`doctor` 默认不请求模型，`doctor --with-llm` 才探测真实端点。
3. 检查 manifest 的文件范围、解析日志或 Tree-sitter parse_report、normalized 图与 prepared 包。
4. 检查局部任务、合并轮次、批次状态、llm_requests 原始响应，再检查 final、候选与冲突。
5. 修正根因后，同一组配置运行失败的单步；合并只运行 merge-schema，AI 审查只运行 review-schema，实例汇总只运行 finalize。合并会先输出合法草稿及对齐问题；审查失败仍保留原始草稿和最近审查候选。合并成功即可直接抽取，AI 审查可选；未审查不能解释为审查通过。

## 3. 常见问题

| 现象 | 检查与处理 |
|---|---|
| 找不到 Python 包 | 项目根目录执行；检查解释器，激活 `.venv` 后 `python -m pip install -e .` |
| 配置文件正确但行为不同 | 系统环境覆盖 `.env`；检查 config 输出与 `--env-file`，不要回显密钥 |
| 找不到 Joern | JOERN_HOME 指向包含 joern.bat、c2cpg.bat 的目录；确认 Java 在同一终端可见 |
| Joern 导出失败 | 看 logs/c2cpg.log、export.log；适配以 Joern 4 flatgraph API 为基线，升级后先做真实解析测试 |
| Windows 路径参数失败 | 空格、中文、等号已处理；工具或输出路径避免批处理拒绝的 `& | < > ^ % ! "` 字符 |
| CFG 为空 | 检查是否只有声明、宏排除了函数体、解析失败或范围遗漏实现文件 |
| Tree-sitter 无 CFG | 当前只支持 AST，选择 tree-sitter + ast；调用表达式不代表目标已解析 |
| 头文件、宏或构建分支缺失 | 配置 CO_INCLUDE_DIRS、CO_DEFINES、CO_COMPILE_COMMANDS，核对真实路径；只读取编译数据库 |
| 401/403 | 核对密钥和服务鉴权，不反复提交同一错误配置 |
| 404 / model not found | BASE_URL 通常以 /v1 结束，不填完整 chat/completions 路由；模型名使用内网服务实际名称 |
| JSON 模式被拒绝 | LLM_JSON_MODE=auto 仅在明确不支持时降级，或设 off；输出仍校验 JSON |
| temperature / thinking 被拒绝 | 通用接口用 LLM_THINKING=auto；确认服务接受的参数，适配集中在 llm.py |
| 非法或空 JSON | 查看 llm_requests；自动修复仍失败时保留状态，缩小任务或调整提示词 |
| length / 输出截断 | 查看拆分恢复和未完成任务；降低 CO_DISCOVERY_BATCH_PACKS 或 CO_MERGE_BATCH_ITEMS，在服务容量内调阶段预算 |
| timeout / 408 / 504 / unknown | 服务端可能仍在计算；先核对服务状态，再显式续跑，不立即重复提交 |
| 请求预算超限 | token 估算使用 UTF-8 保守上界；减小输入包与批量，窗口参数必须符合实际服务容量 |
| Schema 合并无法收敛 | 看 merge-status、rounds、unresolved 和 module-schemas；保留 partial，按使用指南处理独立候选，不能把它称为全局成功 |
| 改合并预算后局部是否重跑 | LLM_MERGE_* 与局部请求隔离；合并阶段键会变化，未变的局部成功请求可复用 |
| 改提示词后 Schema 没变 | 旧组合入口默认复用固定 Schema；按目的显式更新或换实验 ID，新独立阶段检查指纹 |
| extraction 已生成但 final 旧 | 先确认批次完整、指纹一致，再 finalize；仅存在旧文件不代表本次完成 |
| 概念或规则遗漏 | 纳入文件 → 图 → 证据包 → 选包 → 局部发现 → 合并 → 抽取 → 候选，定位第一次丢失 |
| 请求统计突然变成 0 | 可能是缓存恢复成本，不代表首次生成成本为 0 |
| 快照被编辑、来源指纹不一致 | 正常重新 scan/parse；不要篡改证据或正式结果来通过校验 |
| 结果 partial / failed | 看任务清单、失败文件、merge-status 和 run_manifest；保留未完成范围 |
| 配了两轮却没有补跑 unknown | PASS_COUNT 含首次，只自动补跑可恢复失败；unknown 先核查服务状态，再显式续跑原步骤，不能推断服务端已经停止 |
| 实例任务数与包数不同 | CO_EXTRACT_BATCH_PACKS 为每请求包数上限，并发独立；看 extraction/selection.json 的任务与包映射，截断拆分会增加实际请求 |
| RDF 文件存在但命令退出 1 | 看 rdf/export-manifest.json 的 state、upstream_status、shacl_conforms 和 validation-report；上游 partial 或 SHACL 不通过仍保留文件，不是完整成功 |
| 新参数或按钮没有生效 | 运行中任务使用冻结配置；当前任务结束后重启工作台加载后端，下一次任务才使用新配置，不为刷新界面中断现有模型任务 |

## 4. 内网离线迁移

复制源码、prompts、configs、examples、tests、scripts、docs、pyproject.toml、requirements.lock.txt 与 `.env.example`。目标机器重建 `.venv`，单独准备 Java/Joern 与本机 `.env`。不复制外网密钥；已有 `.env` 不覆盖。

无包源时，在匹配目标操作系统、Python 版本和架构的机器上准备 wheel：

```bat
python -m pip download -r requirements.lock.txt setuptools wheel -d wheelhouse
```

在内网项目根目录安装：

```bat
python -m venv .venv
call .venv\Scripts\activate.bat
python -m pip install --no-index --find-links wheelhouse -r requirements.lock.txt setuptools wheel
python -m pip install --no-index --no-build-isolation --no-deps -e .
if not exist .env copy .env.example .env
```

Windows wheel 不直接用于 Linux。迁移已有输出且更换绝对路径可能影响 CPG 和编译数据库，建议重新解析。源码快照是 UTF-8 副本，manifest 保留原始编码与哈希，输入仓库不被改写。

## 5. 日志与时间

内网脚本日志为 `输出根/sessions/实验ID/阶段-时间戳.log`，旁边保存脱敏配置。Joern 日志在快照 logs，模型请求和原始回答在实验 llm_requests，网页控制台在 `.workbench/jobs/任务ID/console.log`。

新模型请求日志使用北京时间前缀，例如 `20261125-165430-123456789-UTC08-<请求键>-initial-0.json`；按文件名升序即可按记录创建时间排列。时间精确到纳秒，并保留请求键、initial/repair/cache 类别及请求尝试序号。响应结束后更新同一文件，文件名前缀仍代表请求开始时间；缓存命中也单独记录时间。旧文件保留原名和原路径，已有日志链接与缓存键不变。正在运行的进程继续采用启动时加载的命名逻辑，新进程使用新格式。

新增日志显示北京时间并带 +08:00；历史 UTC 记录保持原值，网页展示转换时区。请求记录包含源码证据，按内网源码资料管理。一个任务可能包含拆分、修复、重试或缓存命中，不等于一次 API 调用。
