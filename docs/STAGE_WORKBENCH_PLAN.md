# 分阶段可视化工作台方案

日期：2026-11-24。开发分支：`feature/stage-workbench`。第一版已实现，操作以 [WORKBENCH.md](WORKBENCH.md) 为准。下文保留设计目标；实际交付的差异与验证结果见本文第 10 节。

## 1. 目标与边界

用户选择输入仓库、输出根目录、配置、视图和 profile，在浏览器中逐步执行每个可独立运行的阶段，执行后直接查看输入、输出、日志与结果。支持从已有快照继续，不需要重新跑整个仓库。

沿用已有 Python/Joern/LLM 抽取逻辑、输出目录、提示词、缓存和命令。新增任务管理、阶段状态、路径选择和产物浏览层。保留现有只读 viewer；新增可执行 workbench，避免旧 viewer 的只读语义和测试发生变化。

第一版以 Joern 路径完成闭环。可接已有规范化产物；任意 tree-sitter JSON 需要专门适配，不能通过“导入”按钮假定已支持，也不能生成不存在的 CFG/CPG。

## 2. 页面组织

### 工作区设置

表单字段：

| 字段 | 操作与说明 |
|---|---|
| 输入方式 | 代码仓库 / 已有项目快照；规范图导入为高级入口 |
| 输入仓库 | 本机目录浏览与直接输入路径，检查目录存在 |
| 输出根目录 | 本机目录浏览、输入新子目录名；运行前检查可写，禁止设为仓库根或祖先 |
| 已有快照 | 浏览已配置输出根目录，展示来源仓库、快照 ID、文件数量和已有阶段 |
| YAML 配置 | 选择文件，展示最终生效策略及来源；内置 smoke/baseline 可选 |
| 模型环境文件 | 选择 `.env` 路径；显示脱敏有效模型、端点和参数，不返回密钥或环境文件全文 |
| 视图与 profile | 单组优先，另有六组矩阵入口 |
| 实验 ID | 新建或选择已有 ID；明确区分续跑与新对照 |
| 提示词 | 展示实际生效文件、内容和哈希；编辑另存为副本及新配置，记录变更 |

浏览器目录选择由 Python 后端枚举服务所在机器的目录，前端显示目录弹层；它不是把整个仓库上传到浏览器。默认本地使用，选择的是运行 Python 的电脑上的路径。先提供目录浏览和文本输入，不依赖操作系统原生弹窗或浏览器实验接口。

新建工作区得到 workspace ID，保存所选路径与非敏感配置。点击阶段按钮时生成不可变任务配置副本；执行过程中修改页面表单不会改变正在运行的任务。

### 阶段执行页

主页面依次包含工作区设置、阶段列表、选中阶段详情、实时任务栏。

每个阶段卡片展示：阶段名称、状态、输入路径、输出路径、完成数量/耗时、主操作按钮、查看产物。选中卡片后切换详情页签：

- 输入：文件清单、配置、依赖产物、实际命令、内容预览。
- 输出：文件清单、记录数量、分页内容、结构化摘要、下载。
- 日志：实时输出、错误、Joern 日志、模型请求记录。
- 执行记录：attempt ID、开始结束时间、退出码、缓存、取消与恢复信息。

初始没有任何实验产物时也能进入设置与扫描阶段，不能沿用旧 viewer “找到 run 才能显示页面”的前提。

## 3. 第一版按钮与真实阶段对应

| 步骤 | 主按钮 | 现有入口 | 输入 | 主要输出和页面内容 |
|---|---|---|---|---|
| 0 | 检查环境；另有测试模型连接 | doctor --no-llm / doctor | 配置、工具、模型设置 | 诊断 JSON、Joern 能力、模型 JSON 探测结果；标明后者调用模型 |
| 1 | 扫描仓库 | scan | 仓库、纳入排除与解析策略 | 源码快照、manifest、policy；文件树、排除原因与编码告警 |
| 2 | 解析并导出结构 | parse | 同一仓库和固定解析配置 | cpg.bin、三视图节点边、索引、SQLite、Joern 日志；节点/边/符号数量 |
| 3 | 生成模型输入包 | prepare | 所选视图规范图、源码和预算 | packs.jsonl、index；包列表、源码、图上下文、裁剪和未处理项 |
| 4 | 发现并合并 schema | discover | 选中包、领域提示词、连接设置 | 局部 schema、合并轮次、固定 schema、证据与请求；概念/关系/属性表 |
| 5 | 抽取实例与规则 | extract，显式指定 schema | 固定 schema、全部准备包、提示词 | extraction、final、候选/冲突、metrics、单组报告；任务进度和结果图表 |
| 6 | 校验结果 | validate；有适用 gold 时另有 evaluate | 源码、包、schema、正式断言、可选 gold | 结构/证据位置检查；参考概念匹配单独显示，不等于语义通过 |
| 7 | 生成对比报告；查看本体；生成审核表 | report / 复用展示 / review sample | 已有组结果与人工判据 | comparison、图谱、断言、源码证据、审核 CSV；人工完成后再汇总 |

阶段 2 的现有 parse 同时负责解析、导图与规范化；阶段 4 的 discover 同时负责发现与合并；阶段 5 的 extract 同时负责抽取和后处理。第一版对它们提供内部子阶段展示，不提供虚假的独立执行按钮。若以后确实需要“只重新合并 schema”，再以单独变更提取 CLI 边界并验证等价性。

扫描之后解析时仍使用原 scan 的源码/解析设置，校验得到的是相同快照。源文件在两步间变化时，展示新快照并要求重新核对输入范围，不能继续伪装成原快照。输出路径和状态不只靠解析终端中的 SNAPSHOT 文本推断，还要与 manifest 核对。

每个阶段主按钮仅执行本阶段。缺依赖时标明缺少什么并引导到上游；不偷偷重新解析或调用模型。另提供“运行到此阶段”作为显式串行操作，先展示预计阶段与模型调用范围。

## 4. 如何查看抽取产物和 LLM 输入输出

### 图产物

raw 与 normalized 分开。展示视图、文件规模、节点/边计数、节点标签、符号列表、错误与警告。可按文件、符号、节点类型筛选，点击定位源代码。原始 cpg.bin 只展示元数据与下载；不将二进制当文本打开。

### 模型输入包

包列表展示 pack_id、符号、文件行号、大小、视图、裁剪告警。点击可查看源码、签名、上下文、证据 ID 和完整 JSON。独立显示发现阶段已选/未选包以及实例阶段计划包。

### 模型调用

运行前可预览模板、JSON 契约、预计包数量及预算；实际请求生成后展示最终渲染消息、参数、原始回答、校验输出、修复/重试和 token。运行前预览标为“预计”，与真实请求日志区分。

不将上一任务聊天历史自动追加到下一任务；保持当前分阶段调用逻辑。请求日志与源码只在当前工作区范围浏览，环境文件与密钥不进入文件预览。

### 大文件

30 万行产物由后端分页、按记录筛选和限量返回；不一次传给前端或铺满 DOM。JSONL 用记录分页，普通日志用字节偏移增量读取；完整 JSON 使用结构化适配或受限文本片段，提示截断。必要时建立独立 SQLite 浏览索引，索引状态和总量未知应明确显示，不为每次翻页重新完整扫描大文件。

每个预览有记录上限/字节上限，页面显示“当前显示 N 条，共 M 条/总数索引中”。完整产物保留在磁盘。复杂 JSON 的浏览支持不意味着已支持把它转换为模型证据包。

## 5. 后端执行与状态管理

建议新增 workbench 模块及轻量任务管理模块，继续使用 Python 与本地 HTML/CSS/JS，不引入前端构建环境。可复用 viewer 的产物读取与图表组件，保持旧 viewer 路由和行为。

按钮请求交给后端任务队列，通过当前虚拟环境 `sys.executable` 启动已有 CLI 子进程。参数采用列表且 shell=False，固定项目工作目录；页面只传阶段和经过校验的设置，不接收任意 shell 命令。传给子进程的是配置/环境文件路径，密钥由既有配置读取。

建议接口：

| 接口职责 | 内容 |
|---|---|
| 工作区与路径 | 创建/加载工作区、目录列表、配置校验、快照发现 |
| 阶段计划 | 返回实际命令参数、输入/输出、依赖与模型调用标记 |
| 任务管理 | 提交、查询、取消、查看历史 |
| 日志读取 | 按 offset 返回新增输出、子日志摘要 |
| 产物浏览 | 列表、分页记录、受限预览、证据、下载 |

轮询任务与日志即可支持第一版实时反馈，不必先引入 WebSocket。日志记录 UTF-8，使用无缓冲子进程输出减少延迟。

控制信息存于独立 `.workbench/`，任务状态用 SQLite，保存 workspace/job/attempt、配置指纹、进程标识、日志偏移、退出码和产物索引。业务产物仍按既有 outputs 布局写入；控制目录加入 gitignore。密钥不入库。

建议区分任务状态与产物状态：

- 任务：queued / running / succeeded / partial / failed / cancelling / cancelled / interrupted。
- 阶段可用性：blocked / ready；已有产物：missing / current / stale。

退出码、阶段 manifest、失败记录和必要文件共同决定成功；文件存在不等于本次成功。模型全命中缓存时标明“复用缓存”；失败或取消后保留已完成产物，不能展示旧 final 为本次新成功结果。

现有终端提供 discover/extract 任务计数，可展示完成/成功/失败；合并、Joern 等没有可靠总量时显示当前阶段与耗时，不编造百分比和剩余时间。刷新浏览器重新连接同一任务，不重复启动。

默认一次执行一个写任务。对共享快照的解析、规范化、prepare 与读取它们的模型任务设置冲突锁；同一实验目录禁止并发写入，多标签页重复点击以任务 ID 去重。六组串行排队，每组内部模型并发沿用配置。

取消应终止实际进程树，包括 Windows 下 Java/Joern 子进程；进入 cancelling 后待进程结束再释放锁。服务重启时核对存活进程及身份，无法确认的旧 running 标为 interrupted，不能盲目按复用 PID 杀进程或直接启动冲突任务。已有成功请求仍通过原实验 ID 与原配置恢复。

## 6. 配置变化与失败恢复

页面每次执行记录源码/图/包/schema/提示词/有效模型配置指纹，并显示依赖的具体版本。

| 变化 | 页面行为 |
|---|---|
| 源码、宏、头文件或编译配置变动 | 重新扫描确定快照；提示结构产物需重核 |
| 包预算或上下文限制变动 | 包及下游结果标记过期，引导 prepare |
| discover/merge 提示词变动 | 提示固定 schema 不会自动变；提供新实验或显式更新 schema |
| extract 提示词变动 | 可复用 schema，抽取结果需重新生成；独立对照用新 ID |
| 模型或参数变动 | 显示有效设置变化与新请求计划；对照使用新实验 |
| gold 或人工标签变动 | 重做对应评估/汇总，不重新抽取 |

“继续失败阶段”保留原实验和配置，使用现有缓存恢复；“新建对照”生成新实验 ID。更换 schema 后既有实例与审核标签显示版本不一致，不能自动沿用为已审。

## 7. 六组实验与 tree-sitter 的接入位置

六组页沿用 B1–B6：AST/CFG/CPG × general/maintenance。各组有状态、输入包数、schema、实例、失败和成本入口，执行前展示固定条件。原 `experiment` 一次运行六组，页面可先以一个父任务展示，再逐步支持可单组恢复的队列；不会自动把一次运行称为完整人工验收。

tree-sitter 的目标接入位置是“原始产物 → 格式适配 → 规范化/证据包”，后续 schema、实例、校验与展示尽量共用。第一版可提供约定图格式检查与 `import-graph` 高级入口，但必须配套源码快照和合法符号/证据映射。

任意 tree-sitter 适配需先拿到格式样例或字段说明，在本分支另列任务；其未提供的 CFG/CPG 组合显示不支持，不运行六组伪对照。已有内网 Agent 的适配可通过统一文件契约接入，不把大 JSON 直接提交模型。

## 8. 本地运行边界

工作台只监听 127.0.0.1，写操作采用 POST、同源校验和会话令牌；前端源码/日志文本转义。目录读取限定已选择的工作根、仓库与输出根，规范化路径并拒绝越界，不提供任意文件读写或命令执行接口。

第一版不提供网页编辑密钥；只选择已有环境文件并显示连接状态。密钥和含凭据端点在日志/返回值中脱敏。提示词编辑仅允许指定提示词副本目录，不允许写入源码快照或随意覆盖模型结果。

实际启动方式：

```bat
call .venv\Scripts\activate.bat
python -m code_ontology.workbench --port 8766
```

原只读 viewer 仍按原命令在 8765 运行。

## 9. 实现顺序与验收

第一批：独立工作台入口、目录选择、加载已有快照、工作区配置；scan/parse/prepare 按钮；阶段依赖、实时日志、图与包的分页预览。

第二批：discover/extract 按钮；schema 和真实请求/回答查看；validate/report；接入现有图谱与源码证据，贯通单组完整流程。

第三批：任务历史、取消与恢复、过期状态、提示词副本与六组矩阵；评审表生成/汇总。任务锁、配置冻结、基本失败恢复和安全边界随对应功能实现，不能推迟到最后再补。

验收使用现有测试、临时仓库与模拟模型验证编排，再用真实 Joern 验证结构阶段。真实模型只在明确范围内做小例子，不能把模拟结果当语义质量证明。

- [ ] 新输出目录、没有任何 run 时可设置路径并扫描。
- [ ] 每个按钮只运行标明的阶段，缺依赖时给出明确原因。
- [ ] 每阶段可查看实际输入、输出、日志与配置版本。
- [ ] 大文件分页预览不整份加载到浏览器，截断有提示。
- [ ] 任务启动后立即返回；刷新页面可继续查看进度。
- [ ] 重复点击、多标签页和共享快照任务不会冲突写入。
- [ ] 模型阶段显式固定 schema，无意外重新发现/解析。
- [ ] 失败、部分成功、取消与旧产物可以区分，原配置可续跑。
- [ ] 停止任务后 Joern/Java 等子进程确实退出。
- [ ] 网页运行与相同配置 CLI 的产物契约、缓存和校验语义一致。
- [ ] 现有只读 viewer、命令行与测试保持可用。
- [ ] tree-sitter 未适配、缺 CFG 等情况如实显示。

第一版验收目标：在浏览器完成“选目录 → 扫描 → 结构抽取 → 查看图产物 → 生成包并预览 → schema 发现 → 实例抽取 → 校验 → 本体与证据展示”，每一步都能单独停下查看和恢复。

## 10. 第一版实际交付与验证

已交付独立工作台、文件/目录选择、工作区和已有快照、13 个阶段按钮、实际命令和输入路径、日志历史、冻结策略/提示词/Schema、取消进程树、重复点击去重、异常恢复、过期提示、分页预览、提示词副本、原 viewer 嵌入，以及六组父任务。原 CLI、pipeline、prepare 和 viewer 抽取行为未修改。

当前边界：没有“运行到此阶段”的依赖链执行按钮；没有网页规范图导入按钮（可先用原 CLI import-graph）；图节点按文件/符号的专用查询器尚未实现，使用目录/JSONL 搜索预览。文本全文从磁盘取得，网页只提供受限预览和二进制下载。日志用分页读取，未新增专门的子日志摘要。六组仍沿用一个 experiment 父任务，单组恢复可切换视图/profile 后执行对应阶段。目录选择器最多列 150 项，其他位置可直接填路径。

自动验证包含静态/API、任务进程树停止、异常清理、配置冻结、旧 Schema 提示，以及发现结果独立展示与最终版本分离；真实 Joern + 模拟模型通过工作台执行独立阶段、全部六组以及续跑（新增请求 0）。最新测试数量见 [验证记录](VALIDATION.md)。验证脚本为 `scripts/check_workbench.py`，本机证据保存在 `outputs/workbench-verification/verification.json`。Python 编译与 JavaScript 语法检查通过。真实模型语义质量未在本次重新测试。

浏览器预览权限被拒绝，本次未完成浏览器目测和实际点击验收；上面的浏览器端验收清单仍作为人工检查项，不能据自动测试全部勾选。
